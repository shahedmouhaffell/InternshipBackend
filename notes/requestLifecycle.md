# Request Lifecycle

## What Happens Between Typing a URL and Receiving JSON?

عندما يقوم المستخدم بكتابة URL بالمتصفح وبضغط Enter، يوجد عدة خطوات بتصير بالخلفية لحتى المتصفح يقدر يتواصل مع الخادم (Server) ويرجعلي البيانات المطلوبة، مثل JSON.

### 1. Typing a URL

بالبداية نكتب عنوان الموقع أو الـ URL بالمتصفح، مثل:

`https://wsschool.com`

الـ URL هو العنوان اللي بيحدد وين موجود المورد (Resource) اللي بدي أوصل إله.

### 2. DNS Lookup

بعد كتابة الـ URL، المتصفح لازم يعرف عنوان الـ IP الخاص بالخادم.

هون بصير دور DNS (Domain Name System)، واللي بيشتغل مثل دليل عناوين، بحيث بيحوّل اسم الموقع إلى IP Address حتى يقدر الجهاز يتواصل مع الخادم.

مثلًا بدل ما نتعامل مع اسم `w3school.com` فقط، بيتم معرفة عنوان الـ IP المرتبط فيه.

### 3. HTTPS and TLS

بعد معرفة عنوان الـ IP، المتصفح بيبدأ بإنشاء اتصال مع الخادم.

إذا كان الموقع يستخدم HTTPS، بيتم استخدام بروتوكول TLS لتأمين الاتصال وتشفير البيانات المتبادلة بين المتصفح والخادم.

كمان بيتم التحقق من شهادة الخادم (TLS Certificate) للتأكد من هويته.

الهدف من HTTPS هو حماية البيانات من التجسس أو التعديل أثناء انتقالها عبر الشبكة.

### 4. Sending an HTTP Request

بعد إنشاء الاتصال، المتصفح بيرسل HTTP Request إلى الخادم.

الطلب بيحتوي على معلومات مثل:

- **Method:** بتحدد نوع العملية، مثل GET لجلب البيانات.
- **URL:** عنوان المورد المطلوب.
- **Headers:** معلومات إضافية عن الطلب، مثل نوع المحتوى المقبول.

### 5. Server Processing

بعد ما يوصل الطلب إلى الـ Server، الخادم بيستقبل الطلب وبيفهم شو المطلوب منه.

ممكن يعالج الطلب باستخدام Backend Code، ويتحقق من البيانات أو صلاحيات المستخدم، وأحيانًا يتواصل مع Database لجلب المعلومات المطلوبة.

بعد ما يخلص المعالجة، بيجهّز الاستجابة ويرجعها للمتصفح.

### 6. HTTP Response and Status Code

بعد معالجة الطلب، الخادم بيرسل HTTP Response.

الاستجابة بتتكون بشكل أساسي من:

- **Status Code:** بيحدد نتيجة الطلب.
- **Response Headers:** معلومات عن الاستجابة، مثل Content-Type.
- **Response Body:** المحتوى أو البيانات اللي رجعها الخادم.

### 7. Receiving the JSON Response

إذا كانت الاستجابة تحتوي على بيانات بصيغة JSON، بيكون الـ Content-Type غالبًا:

`application/json`

وممكن يكون شكل الـ Response Body مثل:

```json
{
  "id": 1,
  "name": "Shahed"
}
```

المتصفح أو JavaScript بيقدر يتعامل مع هالبيانات ويستخدمها لعرض المعلومات ضمن واجهة المستخدم (UI).

## Conclusion

باختصار، لما بكتب URL بالمتصفح، بتبدأ رحلة فيها عدة مراحل: أولًا DNS بيحدد عنوان IP، بعدين HTTPS بيأمّن الاتصال، وبعدها المتصفح بيرسل HTTP Request إلى الخادم.

الخادم بيعالج الطلب وبيرجع HTTP Response فيها Status Code وHeaders وBody، وإذا كانت البيانات بصيغة JSON، بيقدر التطبيق يستخدمها ويعرضها للمستخدم.

إن ظهور البيانات على الشاشة مو عملية مباشرة، وإنما نتيجة تواصل بين Browser وServer باستخدام مجموعة من البروتوكولات والتقنيات.
